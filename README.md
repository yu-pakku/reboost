# ReBoost

日本語・iPhone優先の個人用学習アプリ。M0〜M5の実装とローカル検証まで対応しています。PWA・オフライン対応・Vercel公開準備を追加しました。実デプロイ・実機iPhone検証・通知・クラウド同期は未実施です。

## 開発

Node.js 22以上を推奨（検証環境: 24.5.0）。`npm ci`、`npm run dev`で起動し http://localhost:3000 を開きます。依存解決にnpm 11.5.1の内部エラーが出る場合は、npm 11.21.1を使用してください。

- `npm run lint`: ESLint（警告も失敗扱い）
- `npm run typecheck`: Next.jsルート型生成 + TypeScript strict
- `npm test`: Vitest / Testing Library / fake-indexeddb
- `npm run build`: Webpackによる本番ビルド（Turbopackの内部ポート作成が制限される実行環境への対応）
- `npm start`: ビルド済みアプリの起動

## M2の使い方

ホームの「知識を追加」から用語と意味を入力し、穴埋め箇所を指定します。説明文を範囲選択して指定する方法と、原文の一部を入力して出現箇所を選ぶ方法があります。意味を変更すると穴埋め箇所の再指定が必要です。問題プレビューを確認して保存してください。

ホームの一覧から検索・詳細・編集・アーカイブ・削除ができます。内容変更は画面内ダイアログで進捗リセット確認、削除は完全削除の確認を要求します。アーカイブ解除は確認のうえLevel 1・成功0回・未定着へ戻します。履歴は編集やアーカイブでは保持し、完全削除時に関連する履歴も削除します。

アカウント画面からJSONを出力し、復元できます。復元は追加方式で、既存の同一ID・同一内容はスキップし、同一IDの異なる内容や設定の競合は全体を拒否します。10MB、知識1万件・履歴10万件を上限とします。これはこの版の操作可能な容量の上限で、IndexedDB自体の上限ではありません。

## 保存形式と責務

IndexedDB名は `reboost`、Dexieスキーマバージョンは1。知識はUUID、日時はUTCのISO 8601、表示はAsia/Tokyoです。初期進捗は `learning / level:1 / successes_in_level:0 / final_attempt_count:0`、`next_due_at`は登録時刻、`mastered_at`は未設定です。学習処理はsrc/domain/review.tsの純粋関数に分離しています。

穴埋めの開始・終了位置はtextareaの選択と同じUTF-16の半開区間 `[start, end)` です。Intl.Segmenterで書記素の境界を検証し、絵文字や結合文字の分断を拒否します。文字数上限はUnicodeコードポイント数です。説明文はトリミング・正規化せず保存し、用語のみ前後空白を取り除きます。答え漏洩と重複警告にはNFKC・英字大小・空白整理を使います。採点にも同じ規則を用い、正答と完全一致するときだけ正解とします。

- `src/app`: App Routerのページと共通スタイル
- `src/components`: 知識管理フォーム・一覧・詳細・バックアップ・共通UI
- `src/lib`: 表示設定、日付・状態ラベル
- `src/domain/knowledge.ts`: データ型、入力／スキーマ検証、穴埋めプレビュー、初期進捗
- `src/data/database.ts`: バージョン管理したDexieスキーマ（knowledge / progress / attempts / settings）
- `src/data/knowledge-repository.ts`: 登録・編集・アーカイブ・削除の原子的な保存と編集競合検出
- `src/data/backup.ts`: JSONの検証・出力・追加復元
- `src/data/use-knowledge.ts`: Dexie liveQueryで保存済み内容を表示に反映

データは同じブラウザ・同じオリジンだけで共有されます。別ポートは別の保存領域です。ブラウザデータ消去やストレージ制限によってデータを失う可能性があるため、定期的にJSONをバックアップしてください。

仕様の基準はSPEC.md、開発時の指針はAGENTS.md、公開手順はDEPLOYMENT.mdを参照してください。M6には着手していません。


## M3の学習とスケジュール

復習タブに「期限超過」「今すべき」「今後」「最終テスト待ち」を表示します。「復習する」で1問を開きます。L1は用語と意味を読み「確認した」、L2は意味から用語入力、L3は登録した原文箇所の穴埋めです。各レベルの2成功目で次へ進み、L3を2回成功すると最終テスト待ちになります。この時点ではまだ定着済みにはなりません。予定時刻を迎えると最終テストを受験できます。

間隔は `src/domain/review.ts` の `REVIEW_INTERVALS` に集約しています。SPECの仮決定値（成功後は順に1・1・1・2・2・3日、不正解は1日）を採用。短い確認から徐々に間隔を広げる暫定設定で、科学的な最適値とは主張しません。1日は24時間で、回答完了の実時刻を起点とします。不正解時はレベル・成功回数を維持し、履歴を残して正答を表示します。その場での写し直しは成功に数えません。

空回答は記録できません。採点はNFKC、前後空白除去、連続空白を半角1文字へ整理、大小同一視の完全一致です。意味の類似性や別名の推測は行いません。L2/L3では回答前に正答をDOMへ表示しません。

「今すべき」は日本時間で当日の期限到来済み、「期限超過」は前日以前の未完了予定です。「今後」は未到来のため回答できません。キューは30秒ごとと画面復帰時に更新し、保存時は正確な時刻で期限を再確認します。アーカイブ・定着済みは復習対象外、最終待ちは受験予定の表示と最終テストへの導線を提供します。

進捗と回答履歴は同一トランザクションで保存。一意な試行ID、出題時の知識更新日時と進捗スナップショット、保存時の状態・期限を確認して、二重タップや別タブの競合を防ぎます。保存失敗時には両方を戻し、同じ試行IDで再試行できます。知識詳細に次回予定と直近20件の回答履歴を表示します。

Dexieの物理スキーマはM2と同じバージョン1です。JSONはM4でバージョン2へ拡張しました（旧v1も読み込めます）。編集時の進捗リセット、履歴保持、削除時の関連履歴削除、アーカイブ、JSON出力と追加復元の方針を維持しています。通知とクラウド同期の処理は含みません。


## M4の最終テスト・可視化・統計

`/test/[id]` で予定到来後に用語入力・穴埋めの2問を解きます。2問の完了後に初めて採点・保存し、2回答と進捗を同一トランザクションで更新します。途中中断・リロードは未完了扱いで、ローカルの入力を破棄します。

全正解は `mastered` と `mastered_at` を保存。不正解なら、失敗形式だけを `relearning_levels`（任意項目、[2] / [3] / [2,3]）に保存して1日後から各2回の再学習を行います。L2のみ失敗なら、L2を2回成功して最終待ちへ進み、成功済みのL3を繰り返しません。両方失敗ならL2からL3へ。最後の再学習成功後は3日待ちます。いずれもSPECの暫定間隔で、実際の完了時刻起点です。

セッションIDと回答ID、知識・進捗のスナップショットによって二重採点と編集後の古い出題への回答を拒否します。通常復習と同じ正規化で完全一致を比較し、意味的な判定はしません。

脳型容器は依存不要のSVGで、定着状態1件につきcircleを1つ描画します。知識IDのハッシュから内側の座標を決めるため、並び替え・再表示・別の粒子追加で既存粒子を移動しません。新しい合格時にだけ短いCSSアニメーションを付け、reduced-motion時は停止します。表示済みの装飾用キーをsessionStorageへ記録します（学習データではなく、バックアップ対象外）。大量粒子では重なりが生じますが、件数表示と描画要素数は一致させます。

アカウントの統計は、通常回答1件と最終テスト1受験を各1回として復習回数を集計します。最終テストの2回答はfinal_session_idでまとめ、合否と日本時間の日別履歴を算出します。登録数はアーカイブを含み、現在の定着・学習中はアーカイブを除きます。編集で定着をリセットしても過去の合格履歴は残り、削除時はその知識の全履歴を除去します。

IndexedDBのストアやインデックスは変更していません。進捗の任意プロパティ追加のため、既存レコードを書き換えるマイグレーションは不要です。旧JSON v1は検証後にv2として読み替えます。v2は再学習対象・2回答のセッションを含み、片方だけの最終テストなど不整合な復元を拒否します。v2を古いM2・M3アプリへ取り込む互換性はありません。

定着済みはアプリ独自の学習達成状態です。永久に忘れないことや概念理解を保証する判定ではありません。


## M5のPWA・オフライン対応

`npm run build`はWebpackビルド後にService Workerと公開資産リストを生成します。`npm start`で確認してください。開発サーバーではSWを登録しません。アプリ用の環境変数は不要です。

ManifestはReBoost／standalone／白基調です。192・512px PNG、maskable 512px、Apple touch icon 180pxを用意しています。既存の星形ロゴ由来の暫定アイコンで、`npm run icons`で再生成できます。

初回オンラインで「オフライン利用の準備ができています。」が出た後、ホーム・一覧・登録・復習・アカウントを保存済み資産で開けます。動的な知識詳細・編集・最終テストは `/offline?route=...` のシェルへ遷移し、既存の端末内データと画面を使います。未完了回答のリロード時の扱いは従来通りです。データ自体はSWへコピーせずIndexedDBに保存されます。

SWは公開HTML6画面とビルド資産・アイコンを保存し、API・認証・RSC・個別知識HTMLは保存しません。接続できないときは保存画面を使っていることを案内します。更新は利用者が入力を保存した後に明示操作で適用し、IndexedDBを消しません。端末時計・期限判定・学習履歴・JSON v2（v1読込可）は従来通りです。

保存領域は端末・ブラウザ・オリジンに依存し、自動同期されません。ホーム画面追加、URL・ドメイン・ポート・プロファイル変更前にはJSONを出力し、新しい起動先で件数を確認してください。初回オンライン準備前やストレージ消去後のオフライン起動は保証できません。

### PWAの検証コマンド

- `npm run test:pwa-http -- http://127.0.0.1:3105`：指定本番サーバーでManifest、PNGサイズ、SWヘッダー、全プリキャッシュ資産のHTTP配信を検査。
- `npx playwright install chromium` / `npm run test:e2e`：オンライン→オフラインの登録・編集・学習・JSON、モバイル幅、SW更新を本番サーバーで検証。テストはローカル3105番を起動し、更新テストは生成済みSWを一時変更して復元します。本番URLへ向けないでください。

この実行環境ではChromium起動時のmacOS Machポート権限制限によりPlaywright本体を実行できませんでした。147件のユニット／統合テストとHTTP配信検査は成功しています。利用可能なブラウザ経由でSW登録・更新・データ保持、サーバー停止中の登録・編集・Level 1学習・再読み込み後の保持・JSON出力／同一内容の復元、320/390px表示を確認しました。実機iPhone、Vercel本番URL、機内モード、L2/L3・最終テスト等のオフライン実操作は未検証です。
